# 02 無人ループ(ループエンジニアリング)

人がセッションを開いて 1 件ずつ頼む代わりに、スクリプトが作業を選び、エージェントに実行させ、結果を機械で判定する。
この仕組みを**無人ループ**と呼ぶ。leadcast-sales の設計(`docs/LOOP_ENGINEERING.md`)を 2026-09-22 に移植した。
このリポジトリの最初の無人ループは、**テストケース表(`docs/tests/*.md`)のうちテストが無い L1・L2 の行を Vitest で実装する**作業だけを回す。

## 1. 用語

| 用語 | 意味 |
|---|---|
| 無人ループ | 下の「1 周」を、人の指示なしで繰り返す仕組み |
| キュー | ループが消化する作業の列。`loops/<名前>/` が 1 つのキュー。定義は [`../../loops/README.md`](../../loops/README.md) |
| 索引 | キューの全件の一覧。順序と「済んだか」を持つ。テストのキューでは `docs/tests/*.md` |
| 1 周 | 作業を 1 件選ぶ → エージェントが実行する → 機械が判定する → 取り込む、までの 1 回 |
| 書く役 | 成果物を作るエージェント(`claude -p` で起動する、画面の無いセッション) |
| 確かめる役 | 書く役の結果を判定するスクリプト(`scripts/loop-run.sh`)。書く役の自己申告は使わない |
| 記録 | `loops/<名前>/<ID>.md`。その項目で試した結果と、人へ渡す理由 |
| 着地 | worktree の変更を `main` に取り込むこと(`scripts/wt-land.sh`) |

## 2. backlog とは別に管理する

`backlog/`(QUESTIONS.md・JOBS.md)は、人が決めることと人が頼む作業を持つ。`loops/` は、ループが消化する同質の作業を持つ。
**無人ループは `backlog/` を読まないし、書かない**(共通ルール 2026-09-21)。接点は、ループが `保留` にした項目を人が読み、必要なら人が `backlog/JOBS.md` に起票すること、だけ。

## 3. なぜテストから始めるか

| ループに向く条件 | テストの実装では |
|---|---|
| 同じ型の作業が多数ある | 表の 1 行が 1 件。書き方は `docs/tests/README.md` §3 |
| 成否を機械で判定できる | `scripts/verify.sh`(ビルド・lint・Vitest・表の整合)が green か |
| 間違えても損失が小さい | 製品のコードに触らない(触ったら不合格) |

このリポジトリでは、**モックのエンジンがサーバの振る舞いの正**(03 §3)なので、L2 のテストはそのまま将来のバックエンドの受け入れテストになる。ループが表を埋めるほど、詳細設計(J-021〜)の受け入れ条件が固まる。

## 4. 1 周の流れ

`scripts/loop-run.sh` を 1 回実行すると、次の順に進む。

1. **止める条件を確認する。**§6 のどれかに当たれば、何もせず終わる
2. **1 件選ぶ。**`origin/main` の索引から、取れる行の先頭を選ぶ(`scripts/loop-next.mjs`)。領域の順は `docs/tests/README.md` §1
3. **書く役を起動する。**専用の worktree(`.claude/worktrees/loop-<id>`)を作り、依頼文を渡す。上限は 30 分
4. **確かめる。**次の全部を満たせば合格
   - コミットがあり、未コミットの変更が残っていない
   - 変更したファイルが「触ってよいパス」(テストファイル・その領域の表・記録)に収まっている
   - `scripts/verify.sh` が green
   - 索引の行にテストの名前が入り、記録が `完了` になっている
5. **合格なら取り込む。**`--land hold`(既定)は worktree を残して止まる(人が差分を見て `scripts/wt-land.sh`)。`--land auto` はそのまま着地
6. **不合格なら記録する。**書く役の変更は捨て、理由を記録に追記して、記録だけを着地させる。同じ項目が 2 回不合格なら `保留`

### 書く役への指示(依頼文の内容)

1. 対象の行と、`docs/tests/README.md` §3、見本(`frontend/src/lib/filter.test.ts`)を読む
2. 記録があれば読み、同じ失敗を繰り返さない
3. テストを 1 件書き、`cd frontend && npm test` で通す。`it` の名前は ID で始める
4. 守りになっているかを確かめる(期待値をわざと変えて落ちることを見てから戻す)
5. 索引の行にファイル名を入れ、記録を `完了(日付)` にして、1 コミットにまとめる。push と着地はしない

次の場合は、テストを書かずに記録を `保留` にして理由を書く: テストを通すには製品(モック・契約)を直す必要がある / 行の文が曖昧、または `docs/design/` と食い違う / その層では確かめられない。

## 5. 状態の置き場

| 情報 | 置き場 | Git |
|---|---|---|
| 何が残っているか | 索引(`docs/tests/*.md`)そのもの | 入れる |
| 試した結果・保留の理由 | 記録(`loops/tests/<ID>.md`) | 入れる |
| 着手中かどうか | worktree `.claude/worktrees/loop-<id>` があるか | 入れない |
| 各周の実行記録 | `~/.cache/perfect-crm/loop/`(`runs.jsonl`・`logs/`・`HALT`・`lock`) | 入れない |

## 6. 止める仕組み

| 条件 | 動作 |
|---|---|
| `~/.cache/perfect-crm/loop/HALT` がある | 起動しない。人が `touch` で作り、消すまで続く |
| 直近 3 周が連続で `failed` | `HALT` を自動で作る |
| 同じ項目が 2 回不合格 | その項目を `保留` にする |
| 書く役が 30 分で終わらない | 打ち切って不合格(`LOOP_AGENT_TIMEOUT`) |
| 別の `loop-run.sh` が実行中 | 何もせず終わる |

着地は必ず `scripts/wt-land.sh` を通る(rebase → verify → push)。verify が red なら `main` に入らない。

## 7. 自律の段階

| 段階 | 起動する人 | 着地 | 次へ進む目安 |
|---|---|---|---|
| 1(現在) | 人が `scripts/loop-run.sh` を実行 | `--land hold`。人が差分を見て着地 | 取り込んだ差分に手直しが要らない状態が続く |
| 2 | 人、またはタイマー | `--land auto` | `保留` と不合格の理由が妥当で、放置しても害が無い |
| 3 | タイマー | `--land auto` | — |

ループは `claude` の認証と Node が要るので、**この PC(WSL2)でしか動かない**。

## 8. コマンド

| コマンド | すること |
|---|---|
| `scripts/loop-run.sh` | 1 周を回す(`--land hold`) |
| `scripts/loop-run.sh --land auto --max 3` | 最大 3 周を続けて回し、合格したら着地まで行う |
| `scripts/loop-run.sh --dry-run` | 次の 1 件と依頼文を表示するだけ |
| `node scripts/loop-next.mjs --list` | 実装済み・取れる行・着手中・保留・対象外の件数 |
| `node scripts/loop-next.mjs --check` | 索引と、実在するテスト・E2E のラベル・記録との食い違いを検査する |
| `scripts/verify.sh` | ビルド・lint・Vitest・表の整合をまとめて回す |

## 9. 前提と落とし穴

- **ループは `origin/main` から選ぶ。**表を直したら push しないと、ループには見えない
- worktree は本体の `frontend/node_modules` をシンボリックリンクで共有する。依存を足したら本体で `npm install` してから回す
- `verify.sh` に E2E は含めない(開発サーバと Chromium が要る)。L3 の行は人が `npm run e2e` で確かめる
