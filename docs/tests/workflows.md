# ワークフロー(WF)テストケース表

読み方・資産の書き方・`—` の扱いは [`README.md`](README.md)。仕様は `docs/design/04` §15、`02` §7、`03` §11、`05` §14。
送り先の Slack のチャンネルは [`settings.md`](settings.md) §6。

**段階**: `定義`(作る・直す・削除)、`発火`(書き込みのたびに、動かすかを決める)、`送信`(送り係がアクションを動かす)、`移行`(これまでの Web フォームの通知を置き換える)、`画面`。
この領域は**優先順位の 7 位**(知らせ損ねる・知らせすぎる。どちらも Slack の向こうの人に見える)。

L2 の対象は `frontend/src/mocks/workflows.ts`(定義の検証と、書き込みの口 `setWriteHooks` に差し込んだ判定)。モックには Slack が無いので、
動いた実行はその場で「済み」になる。送信の中身(本文・エスケープ)と、送り係の試し直し・見送りは API の資産(`test_workflows.py`)だけが確かめる。
