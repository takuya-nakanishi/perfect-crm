# 07 移行

これまでの顧客管理と Todoist を、Works へ移す計画(01 §1)。**まだ何も移していない。**実データを入れるのはバックエンドができてから(段階 2)。
ここに書いた移行元の構造は 2026-09-19〜21 に実物を確認したもの。

## 1. 移行元と行き先

| 移行元 | 行き先 | 取り方 |
|---|---|---|
| 退避済みの連絡先台帳(企業 60・人 25) | 取引先・取引先責任者 | `~/backups/perfect-crm/twenty-companies-2026-09-21.csv` / `twenty-people-2026-09-21.csv`。いちばん整っているので最初に入れる |
| Notion「プロスペクト」(人) | 取引先責任者 + 取引先(企業名から名寄せして起こす) | Notion API(MCP あり) |
| Notion「案件-プロジェクト」 | 商談 | 同上 |
| Notion「活動の記録」 | **行き先が無い**(初回ローンチに活動のテーブルは無い)→ Q-042 | |
| Google コンタクト | 取引先責任者 | People API か CSV。Notion・台帳と重なるので名寄せ |
| Todoist | タスク | Todoist API(MCP あり) |

規模は合計 1,000 レコード程度。性能の心配は要らない。

**個人情報なので Git に入れない**(このリポジトリは公開)。退避先は `~/backups/perfect-crm/`。台帳の原本は Google ドライブ `マイドライブ/連絡先台帳-移行元-2026-09/`。
同じ場所に、撤去した連絡先台帳と Twenty の `pg_dump` もある。

## 2. 移行元の構造

### 退避済みの台帳(CSV)

企業: 名称、略称、種別、状態、Drive フォルダ(パス文字列)、wiki 名、メモ、旧 ID(`o0001`)。
人: 氏名(**姓名の区切りが無い**。25 件とも 1 つの文字列)、フリガナ、役職、所属企業、種別、状態、メモ、旧 ID(`p0001`)。
メール・電話・接触日は元データが全件空。

### Notion(3 つの DB がリレーションで結ばれている。ページ「🏄🏻 【人脈】リード＆仲間」の配下)

**プロスペクト(人)** — `名前`、`Furigana`、`企業名`(**テキスト。企業の DB は無い**)、`部署名`、`役職名`、`メール1` `メール2`、`電話1` `電話2`、`住所`、`誕生日`、`出身地`、`TOBE`(複数選択: BP / 友達 / リード ほか)、`メモタグ`(複数選択: Web問合せ / 師匠 / コンサル・Engineer / 転職・SES Agent / 営業 / SES可 / 専門家-士業 / 取引先 / 社長)、`最終タッチ日`、`次のアクション`、`特記事項`、`SF取引先ID` `SF取引先責任者ID`(Salesforce の残骸)、案件と活動へのリレーション。

**案件-プロジェクト** — `プロジェクト名`、`ステータス`(1-新規 / 2-案件理解/見積 / 5-受注 / 6-完了。3・4 は欠番)、`客先担当者`・`請求先担当者`(プロスペクトへ、各 1 件)、`担当者`、`決済条件`、`完了/予定日`、`次のアクション`、`案件NO`。**金額の項目は無い。**

**活動の記録** — `件名`、`日付`、`タグ`(ビジネスアイデア / KPI交流 / 健康 / 活動 / マインド / ナレッジ / WORK / 日記 / 読書・勉強 ほか。**私的な記録が同居している**)、`場所`、`振り返り／NEXT`(電話番号型になっているが設定ミス。テキストとして読む)、プロスペクトと案件へのリレーション。

## 3. 対応

| 移行元 | Works |
|---|---|
| 台帳の企業 `名称` / 人の `氏名`・`フリガナ`・`役職`・`所属企業` | 取引先 `name` / 取引先責任者 `name`・`name_kana`・`title`・`account_id` |
| 台帳の `種別`・`状態` | 取引先 `type`、取引先責任者 `status`。値の対応は入れるときに決める |
| 台帳の `旧 ID`・`略称`・`Drive フォルダ`・`wiki 名` | 対応する列が無い。項目を足すか、`description` に寄せるかを入れるときに決める(突き合わせと再実行のため、旧 ID はどこかに必ず残す) |
| プロスペクトの `企業名`(テキスト) | 表記を正規化して名寄せし、取引先を起こす。判断がつかないものは保留の一覧へ。企業名が空の人(友人・師匠)は、所属なしの取引先責任者にする(`account_id` は任意) |
| プロスペクトの `最終タッチ日` / `次のアクション` | 取引先責任者 `last_contacted_on` / タスクとして起こす(期限なし) |
| プロスペクトの `TOBE`・`メモタグ` | 取引先責任者 `role`・`status` に寄せきれない。ラベルのような複数選択の項目が要るかは Q-037 と併せて決める |
| 案件の `ステータス` | 商談 `stage`。1-新規 → 見込み、2-案件理解/見積 → 見積、5-受注・6-完了 → 受注 |
| 案件の `客先担当者` / `完了/予定日` / `次のアクション` | 商談 `primary_contact_id` / `close_date` / `next_step`。金額は NULL で入れ、あとから手で入れる |
| Todoist のタスク | タスク `title`・`description`・`due_date`・`priority`(**Todoist の API は 4 が最優先で、表示の P1 と逆**)。プロジェクト・セクション・ラベル・繰り返し・コメントの扱いは Q-037 |

## 4. 方針

- 移行は、**バックエンドの書き込み経路を通す**スクリプトで行う(検証と業務ルールが効く。DB へ直接流し込まない)
- 元の ID を必ず残し、再実行しても重複しないようにする。件数と項目ごとの一致を、元データと機械的に突き合わせる(Twenty へ入れたときのやり方。スクリプトは `~/backups/perfect-crm/migration/` に残っている)
- 順序: 台帳の CSV(整っている)→ Notion(名寄せが要る)→ Google コンタクト(重なりを見る)→ Todoist

## 5. 切替(Todoist の廃止・J-027)

旧サービスを止めるのは、次を全部満たしてから。満たす前は Notion と Todoist を正のまま、Works には試しに流すだけ。

- Q-037 で「要る」と決めた Todoist の機能が Works で動く
- スマホから日常のタスク操作ができる(Access のセッションが切れたときの入り直しも含めて実機で確認)
- バックアップと復元が回っている(J-025)
- 移行の件数と抜き取りの照合が済んでいる
- 切り戻しの手順(元データを残す期間と戻し方)が書けている

手順: ①凍結日を決めて旧サービスの更新を止める ②移行を流す ③照合 ④切替 ⑤2 週間は元データを残し、その後アーカイブ。
Todoist の完了時に llm-wiki へ取り込む今の運用(`todoist-complete` skill)は、MCP(J-028)ができたら Works 向けに書き換える。
