# 01 要件と決定

Works(このリポジトリで作る自作 CRM)が何であり、何を決めたか。決定には理由を付ける。
決定を変えるときはこの文書を更新し、`backlog/QUESTIONS.md` の該当項目にポインタを残す。

## 1. 目的と性格

- **あり物を使わず、完全に AI で自作する CRM。**GAS・NocoDB・Twenty などの既製品を試したうえで、挑戦として自作に切り替えた(2026-09-21、本人の決定。それまでの経緯は README)
- これまでの顧客管理(Notion・Google コンタクト・退避済みの連絡先台帳)をこの仕組みに置き換え、**Todoist も廃止する**のが到達点
- 命は 3 つ。**きれいで「イケてる」画面、使いやすさ、サクサク動く軽快さ。**機能の数より、この 3 つを落とさないことを優先する
- 利用者は当面 1 名(本人)。画面とデータの作りは複数人を妨げないが、複数人のための機能(権限の細分化、招待)は作らない

## 2. 初回ローンチのスコープ

| 領域 | 中身 |
|---|---|
| テーブル | **取引先・取引先責任者・商談・タスク**の 4 つ |
| タスク | Salesforce の Task と同じく、各テーブルのレコードに紐づく(関連先 + 取引先責任者)。何にも紐づかない個人のタスクも持てる(Todoist の代わり) |
| ビュー | **一覧・カンバン・レポート(グラフと集計)。**テーブルを開いた画面の中で、タブで切り替える |
| 画面の骨格 | Notion / Twenty 風。左のサイドバーに DB のテーブルが並ぶ |
| 操作 | Todoist の気持ちよさ。完了のチェックで即座に一覧から消える。`Q` でタスク追加、`/` で検索。マウスなしで一周できる |
| ログイン | Cloudflare Access のログイン(PIN か Google)を使い、アプリはログイン画面を出さない(2026-09-24 に変更。03 §5) |

ローンチ後に回したもの(`backlog/JOBS.md`): MCP サーバ、サイドバーの AI チャット、ドキュメントの採番・命名ルールの整理。
**テーブルを画面から追加・設定する機能(Airtable / kintone 風)は、2026-09-22 に本人の指示で前倒しし、モックに入れた**(画面は 05 §8、契約は 04 §6、決まりは 02 §5)。バックエンド側は J-033。

## 3. 決定

### D-01 画面はメタデータで描く

- テーブル・項目・ビューの定義を**データ**として持ち(02 §1)、画面はそれを読んで描く。サイドバーに並ぶのは DB のテーブルそのもの
- 理由: ローンチ後に「テーブルを画面から追加する」をやるとき、画面を作り直さずに済む。取引先専用・商談専用の画面を 4 枚作ると、5 枚目を足すたびにコードが要る
- 帰結: 画面のコードにテーブル名・項目名を書かない。例外は「タスクの追加欄(Q)」だけで、それも `completion` を持つテーブルをメタデータから探している

### D-02 画面とバックエンドは JSON の契約で分ける

- 画面は SPA、バックエンドは Python の JSON API。契約は 04 と `frontend/src/api/types.ts`(型が正)
- 画面は `ApiClient` という窓口 1 つだけを通してデータに触る。実装は **mock**(ブラウザ内の擬似 DB)と **http**(本物の API)の 2 つで、環境変数 1 つで切り替わる(03 §3)
- 理由: バックエンドが無いうちから画面を完成させられ、できたら差し替えるだけで済む。モックのデータは DB の行と同じ形(列名は snake_case、ID は UUID、参照は ID)なので、プログラムの返り値をそのまま差し込める

### D-03 画面のスタック: Vite + React + TypeScript + Tailwind CSS v4

- 軽快さの要は楽観更新とキーボード操作で、どちらも SPA が向く。React は部品(ドラッグ&ドロップ、データ取得のキャッシュ)が最も揃っている
- 見た目は全面的に Tailwind CSS。色・文字・影・動きはトークンとして `frontend/src/styles/index.css` に定義する(05 §4)
- 採用したライブラリと、非推奨でないことの確認結果は 03 §9

### D-04 バックエンドは Python、DB は PostgreSQL。フレームワークは未決

- 言語は Python(本人の決定)。フレームワークは議論して決める → **Q-034**。比較と推奨は 03 §4
- DB は PostgreSQL 18。Compose に定義だけ置いてある(バックエンドを足すまで起動しない)

### D-05 Docker Compose で動かす。Docker は WSL2 の中のものを使う

- いまは Surface(WSL2)で動かすが、いざというとき AWS などへ引っ越せるよう、最初から Docker で組む。状態を持つのは PostgreSQL だけにし、画面と API のコンテナは無状態に保つ
- **Windows 側の Docker Desktop は使わない。**WSL2 の Ubuntu に入れた Docker Engine を使う(`docker context` の `default`)

### D-06 公開は Cloudflare Tunnel + Cloudflare Access、`works.sanei-clover.com`

- Surface から Cloudflare へ外向きに張るだけで、受信ポートを開けない。DNS は Cloudflare(共通ルール)
- 前段に Cloudflare Access を置き、本人のメールアドレスだけを通す。セッションは 30 日(短いと PIN の往復が日常の負担になる。Twenty のときはそれが理由で Access を外した)
- アプリ自身のログインは **Access を信頼する**(2026-09-24。J-023)。Access の JWT のメールアドレスで利用者を決め、アプリはログイン画面を出さない。03 §5

### D-07 タスクは「関連先」と「取引先責任者」の 2 本で紐づく

- 関連先 = 取引先か商談のどちらか 1 件(`related_object` + `related_id`。Salesforce の WhatId)。取引先責任者 = 人(`contact_id`。同 WhoId)
- どちらも空でよい。空のタスクが Todoist の代わりの個人タスク
- 関連先になれるテーブルはメタデータ(`targets`)で決まるので、テーブルが増えても同じ仕組みで紐づく

### D-08 操作は Todoist に寄せる

- 完了はチェック 1 回。押した瞬間にチェックが入り、行が抜け、「元に戻す」が出る。確認ダイアログは出さない(削除も同じ。取り消せることで守る)
- 追加は `Q`。件名に「明日」「金曜」「9/30」「p1」と書けば期限と優先度として読む。レコードを開いた状態で `Q` を押すと、そのレコードが関連先に入る
- キーの一覧は 05 §3。日本語入力の変換中は、どのショートカットも反応させない

### D-09 デザインは Anthropic 公式の skill に従って決める

- 画面全体は `frontend-design`(claude-plugins-official)、グラフは `dataviz` の手順で決めた。配色・書体・動きの決めごとと、その理由は 05 §4
- グラフの色は目で選ばず、`dataviz` の検証スクリプトを通した値だけを使う

### D-10 データの置き場と個人情報

- モックの間、データはブラウザの中(localStorage)だけにある。フィクスチャの会社・人物はすべて架空
- **このリポジトリは公開。個人情報は Git に入れない。**実データの退避先は `~/backups/perfect-crm/`(07)

### D-11 AI の入口は 2 つ。どちらも同じコマンド層を通す(ローンチ後)

- **外から**: MCP サーバを公開し、Claude Code や Codex からレコードを読み書きする(J-028)
- **中から**: サイドバーをチャット欄に切り替えられるようにする(Notion AI / Twenty 風。J-029)。LLM は **Amazon Bedrock でも、個人の Claude API キーでも使えるように差し替え可能にする**(本人の前提。設計は 03 §7)
- どちらも、画面と同じ書き込み経路(検証・業務ルール・記録)を通す。AI 専用の抜け道を作らない

## 4. 非機能要件

- **軽快さ**: 一覧・パネル・タブの切り替えは体感で即時。更新は楽観的に反映する。最初に読む JS は 120KB(gzip)程度に抑え、カンバンとレポートは遅延読み込み
- **きれいさ**: 明暗の両テーマ。和文は OS の UD 系ゴシック、欧文と数字は Figtree。太さは 2 段階だけ(05 §4)
- **キーボード**: 主要な操作はすべてキーで届く。フォーカスの輪郭を消さない
- **スマホ**: 同じ画面がそのまま使える(サイドバーは引き出し、パネルは全画面)
- **日本語**: 検索はひらがな・カタカナ・全角半角を区別しない。金額は円、日付は「今日・明日・9月30日(水)」

## 5. 制約(全リポジトリ共通ルール由来)

- DNS は Cloudflare。非推奨のツール・ライブラリを使わない(採用前に一次資料で確認する。結果は 03 §9)
- 問いと作業は `backlog/`。設計の正はこの `docs/design/`。文章は日本語
