# loops — 無人ループの置き場

**無人ループ**とは、人が 1 件ずつ頼まなくても、スクリプトが作業を 1 件選び、エージェントに実行させ、結果を機械で判定する仕組み。
設計の全体は [`docs/runbook/02-loop.md`](../docs/runbook/02-loop.md)。leadcast-sales の `loops/` と同じ型(2026-09-22 に移植)。

## backlog との違い

| | `backlog/`(QUESTIONS.md・JOBS.md) | `loops/` |
|---|---|---|
| 誰が読むか | 人と、人が起こしたセッション | 無人ループのスクリプトとエージェント |
| 中身 | 人が決めること・人が頼む作業 | ループが消化する作業の記録 |
| 終わりの判定 | 人が決める | 機械が判定する |

**無人ループは `backlog/` を読まないし、書かない。**ループから人へ渡すものは、下の「記録」の `保留` だけ。
人はそれを読み、必要なら自分で `backlog/JOBS.md` に起票する。

## キューとは

**キュー**は、ループが消化する作業の列。`loops/<キュー名>/` が 1 つのキューで、次の 9 項目で定義する。

| 項目 | 意味 |
|---|---|
| 名前 | ディレクトリ名。`loops/<名前>/` |
| 1 件の単位 | 何を 1 件と数えるか |
| 索引 | 全件の一覧。**順序と「済んだか」は索引だけが持つ**(他の場所に写さない) |
| 取れる条件 | 索引のうち、ループが取ってよい項目の条件 |
| 成果物 | 1 件につきエージェントが作るファイル |
| 触ってよいパス | エージェントが変更してよいファイル。これ以外を変更したら不合格 |
| 合格条件 | 機械が判定する条件。エージェントの自己申告は使わない |
| 記録 | `loops/<名前>/<ID>.md`。書式は下 |
| 起動 | 1 件を回すコマンド |

## 記録の書式(`loops/<キュー名>/<ID>.md`)

索引に書けないこと、つまり**試した結果**と**人へ渡す理由**を残すファイル。ループが触った項目にだけ作る。
次にその項目を取るとき、このファイルの全文がエージェントへの依頼文に入る。

```markdown
# META-004

- 状態: 保留(2026-09-22): 削除済みの列名で作らせない規則が、モックにまだ無い

## 試行の記録

- [2026-09-22 03:10] 失敗: verify が red(frontend:test)
- [2026-09-22 09:10] 保留: 製品側の修正が要る
```

`状態:` の値は 4 つ。

| 値 | 意味 | ループの扱い |
|---|---|---|
| `未着手` | まだ成功していない(ファイルが無い項目も同じ) | 取る |
| `完了(日付)` | 成果物ができ、合格した | 取らない(索引も「済み」になっている) |
| `保留(日付): 理由` | ループでは進められない。人の判断か、製品側の修正が要る | 取らない |
| `取り下げ(日付): 理由` | 人がやめると決めた | 取らない |

`保留` を解除するのは人。理由を読んで原因(索引の行の誤り・製品の不具合など)を直し、`状態:` を `未着手` に戻す。
「着手中」は記録に書かない。その項目の worktree(`.claude/worktrees/loop-<id>`)があれば着手中と見なす。
